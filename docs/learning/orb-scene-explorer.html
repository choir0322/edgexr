Recognize a view when a person passes through

MobileNet-SSD and ORB answer different questions. The detector identifies a person; ORB checks whether the remaining background matches a view you chose to remember.

What is compared?

The reference stays intact. On the query, ORB avoids person-box pixels and descriptor neighborhoods that overlap them. Matching features outside the box are checked against the stored view.

A rectangle may also cover background. A person the detector misses may remain in the usable area; the system does not have a pixel-accurate silhouette.

Other object labels: MobileNet-SSD can detect objects such as chairs and bottles, but the current scene mask excludes only the person class. It does not add semantic object memory or decide that furniture is stationary.

Known

Enough visible features match a reference with consistent geometry and spatial distribution, without an equally strong competing view.

Unknown

Too little visible background, poor geometry, competing references, or unavailable/stale evidence makes the result uncertain. A partial match is not automatically accepted.

Timing, enrollment and the live evidence panel

Same image: the detector retains one latest completed package containing its source frame, its boxes and the orientation context captured for that frame. The scene worker uses that exact frame and boxes at a target of 1 Hz; source age at selection must be at most 1.5 seconds. Old packages are replaced, not queued. Host timestamps are not camera exposure synchronization.

Remember: with person exclusion enabled, a post-click image with any detected person-box mask is rejected as clear_background_required. Waiting for an eligible image or recording capacity expires after 8 seconds; this is not a hard real-time bound on processing. An empty detection result does not guarantee the view is person-free.

Partial-query safeguards: existing feature/match/inlier counts, geometry, footprint and ambiguity checks remain. The experimental partial policy checks visible support in the query and projected reference, including absolute minimum area, visible-area fraction and grid-cell coverage. It may still abstain when enough information is not spread out.

Where do the IMU, motion worker and person detector fit?

The nine-patch Hann/FFT motion worker measures image displacement separately. It does not supply ORB descriptors. The IMU attaches host-timestamped relative orientation to the recognized view; it does not override a failed visual match.

With --scene-exclude-people, the detector's completed source frame and person boxes are paired. Enrollment requests need a clear detected view; queries use a mask. This nine-stage teaching replay has foreground exclusion off; the live extension is explained above.

Scene worker: latest eligible detector/image pair, target 1 Hz → result mailbox → view map → HTTP/browser. Selected evidence goes to a bounded background writer. “Known” is visual overlap, not a measured physical position.

What this teaching replay does—and does not—measure

Images are existing small derived frames from your Pi, already stored in this repository. The 320×180 reference is enlarged to canonical 640×360 for this example; the real live scene branch starts with 1280×720 and reduces it. Enlargement does not restore detail. No private images from the person trial are embedded.

The browser draws precomputed OpenCV results. It does not run ORB, RANSAC, an IMU or a live camera. Lines are thinned for readability; the counts use every match. The animation advances stages, not hardware time. Stage 4 enrolls the reference once; later stages query it, rather than re-enrolling every frame.
