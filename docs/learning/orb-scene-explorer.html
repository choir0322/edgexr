Where do the IMU, motion worker and person detector fit?

The nine-patch Hann/FFT motion worker measures image displacement separately. It does not supply ORB descriptors. The IMU attaches host-timestamped relative orientation to the recognized view; it does not override a failed visual match.

With --scene-exclude-people, fresh person boxes become an allowed-feature mask for both enrollment and queries. Detector source lag must be 0–500 ms relative to the scene source. Missing/stale evidence yields unknown; too little background support also yields unknown. A recent box can still be misaligned. This replay has foreground exclusion off.

Scene worker: latest fresh full frame, target 1 Hz → result mailbox → view map → HTTP/browser. Selected evidence goes to a bounded background writer. “Known” is visual overlap, not a measured physical position.

What this teaching replay does—and does not—measure

Images are existing small derived frames from your Pi, already stored in this repository. The 320×180 reference is enlarged to canonical 640×360 for this example; the real live scene branch starts with 1280×720 and reduces it. Enlargement does not restore detail. No private images from the new person trial are embedded.

The browser draws precomputed OpenCV results. It does not run ORB, RANSAC, an IMU or a live camera. Lines are thinned for readability; the counts use every match. The animation advances stages, not hardware time. Stage 4 enrolls the reference once; later stages query it, rather than re-enrolling every frame.
