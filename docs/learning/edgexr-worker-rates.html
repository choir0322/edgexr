EdgeXR learning lab · current live-preview architecture

One camera, independent workers

A camera frame splits into two image branches. The IMU runs from its own sensor. The browser collects whatever each worker has finished.

1 · Camera + FFmpeg

30 fps ≈ every 33.3 ms

1280×720 MJPEG over USB; FFmpeg decodes it to grayscale. Actual spacing varies.

Recent arrivals (one F-number, both sizes)

Camera-mounted IMU

Independent of camera fps

A separate source: gyro samples over I²C, never camera frames.

2 · Capture worker

Every arriving frame

read_frame() collects exactly 921,600 bytes; a partial frame at stream end is an error. OpenCV makes the 320×180 copy; both sizes share one sequence number and receipt time.

  • State.latest: 320×180, to motion
  • State.detection_frame: 1280×720, to detection
  • Latest wins: a new frame replaces waiting work.

3A · Motion worker

As soon as ready

Compares the previous processed frame with the newest small frame.

Accept a shift

  • Patch stddev ≥3; peak quality ≥8.
  • ≥4 patches agree within 1.5 px of the median.
  • Gap >500 ms resets the reference.

→ State.result · analyze_latest() · image_shift()

3B · Detector worker

Starts ≥500 ms apart

Takes the newest full frame at each start; frames in between are bypassed, so there is no backlog.

Accept boxes

  • Score ≥0.5; positive area after clipping.
  • Source older than 1.5 s is skipped.
  • Zero boxes is a valid result.

→ detector.result · detect_latest() · parse_detections()

3C · IMU reader

Read, then pause 50 ms

≈19 samples/s, each stamped at its read's midpoint.

Startup offset

  • Rig still for ~1 s; ≥10 samples.
  • Per-axis stddev ≤0.5°/s, else restart.

→ imu.latest · poll_imu() / LiveImu

4 · State.snapshot()

On each browser request

GET /api/frame gathers each worker's latest result. Combining them does not synchronize the original observations.

Hide when stale

  • Motion: age >2 s.
  • Boxes: age >1.5 s or camera down.
  • IMU: age >300 ms.
