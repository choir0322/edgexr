01 / THE INPUT

One scene, two viewpoints

You moved the whole camera rig right. Two images were selected at approximately 5 s and 15 s of the recorded video. Nearby and distant objects change position by different amounts as the camera translates.

The rig moved; a pure pan or tilt does not provide the same translation needed for depth. The IMU was recorded but was not used to estimate these 3D points.

02 / FIND CORRESPONDENCES

Find the same image details twice

ORB finds textured details in each image. Their descriptors help the program match details that look alike, then geometric checks keep matches consistent with a pair of camera views.

The trial found up to 3,000 ORB keypoints in each view. Matching is evidence about corresponding image features; it does not identify every object or guarantee each correspondence is correct.
03 / ESTIMATE GEOMETRY

Two rays suggest one 3D point

The camera calibration converts image locations to viewing rays. The program estimates the relative camera pose, then triangulates where corresponding rays meet. Depth is expressed in arbitrary baseline units.

The 0.40 px statistic measures image fit for points used by the estimate; it does not prove the scene's 3D depth is correct.

04 / INSPECT THE CLOUD

Nearly every point landed on the bookshelf

We projected the original Pi cloud back onto the first camera image and counted the locations. The image is 720 pixels tall. These are actual counts; the scene drawing is an illustration.

A cloud can fit its image measurements well while representing mostly one distant surface. The first result does not yet demonstrate a useful reconstruction of both foreground and background.
05 / THE CHANGE

A stronger coverage check

The original rule checked whether points occupied three image quadrants. A few isolated points could satisfy it even when the cloud was concentrated in one area. The revised rule requires meaningful support in both vertical halves of each view.

This is a provisional coverage rule, added after inspecting this scene. A passing result still needs geometry review and does not guarantee multiple depths or metric accuracy.

Next: add a textured stationary object closer to the camera in the lower image, while keeping the distant bookshelf visible. A successful pair can then be checked against a third view.

Recorded pair comparisons and interpretation

The 15/27 s pair yielded 279 geometry points but failed the original quadrant gate. The 27/45 s pair produced 399 geometry points and passed the revised gate. Its independent two-view cloud is not registered to the 5/15 s cloud and does not establish a shared multi-view map.

The original Pi run produced 309 points; the Mac rerun produced 299 due to a different RANSAC result. For that rerun, 298 points above and one below the principal-point line appear in each view. These results should not be mixed as if they are one run.
